## 이번 실습에서 만드는 것

- 내 컴퓨터(윈도우)에 설치된 프로그램 1개

다음 회차에는 같은 앱의 다른 칸을 엽니다. 오늘 쓴 코워크 옆에 있는 칸이에요.
그 칸이 열리려면 윈도우에 프로그램 하나가 더 있어야 합니다. 오늘 그것만 깔아둡니다.

이건 배우는 게 아니라 준비물입니다. 무엇에 쓰는 물건인지는 뒤 회차에서 제대로 다룹니다.

**이 실습만은 빠지시면 다음 회차에 손을 못 댑니다.** 다른 실습은 못 따라오셔도 뒤에서 만회가 되는데,
이건 안 깔려 있으면 화면 자체가 안 열립니다.

이 설치는 컴퓨터를 한 번 껐다 켜야 완전히 잡힙니다. 그래서 미리 깔아둡니다.

### 맥 쓰시는 분

맥에는 대부분 이미 들어 있습니다. **Step 1·2는 건너뛰고 Step 3만** 해주세요.
맥은 **터미널**을 열어 같은 `git --version` 을 치시면 됩니다. (검색에서 `터미널` 로 찾으시면 됩니다)

## 이렇게 해보세요

### Step 1. 내려받기

주소로 바로 갑니다. 검색하면 비슷한 이름이 여럿 나와 헷갈립니다 — https://git-scm.com

1. 위 주소로 들어갑니다
2. 화면 오른쪽 아래에 주황색 `Install for Windows` 단추가 있습니다. 그걸 누릅니다
3. 화면이 한 번 바뀝니다. 여기서 끝난 게 아닙니다
4. 바뀐 화면 위쪽에서 `Windows` 칸이 눌려 있는지 보고, 그 아래 파란 글씨 `Click here to download` 를 누릅니다

- 단추를 두 번 누르는 게 맞습니다. 첫 번째는 안내 페이지로 넘어가는 것뿐입니다
- 바뀐 화면의 아래 목록(`Standalone Installer`, `Portable`, `winget` 등)은 다른 방법들이라 안 보셔도 됩니다
- 적힌 숫자(`2.55.0` 같은)는 판 번호입니다. 보실 땐 다른 숫자일 수 있고, 늘 최신 것이 내려받아집니다
- 바로 아래 `GitHub Repository` 는 누르지 마세요. 프로그램이 아니라 개발자용 페이지로 갑니다

![git-scm.com 첫 화면 오른쪽 아래의 주황색 Install for Windows 단추](/samples/guides/lab-11-1.jpg)

![바뀐 화면에서 Windows 칸 아래의 파란 글씨 Click here to download](/samples/guides/lab-11-2.png)

### Step 2. 설치하기 — 기본값 그대로

받은 파일을 두 번 누릅니다. 화면이 여러 번 넘어갑니다.
**전부 기본값 그대로 두고 다음을 누르시면 됩니다.**

선택 화면이 많아 보여도 괜찮습니다. 고르라고 띄운 게 아니라 이미 골라져 있습니다.
설치 화면이 길게 이어지는 게 정상입니다.

딱 하나만 봐주세요. 중간에 `PATH` 라는 말이 나오는 화면이 있습니다.
거기서 가운데 항목이 골라져 있으면 맞습니다. 기본값이 그것이니 바꾸지 마세요.

### Step 3. 잘 깔렸는지 확인하기

설치 화면이 끝났다고 다 된 게 아닙니다. 한 줄로 확인할 수 있습니다.

1. 시작 단추 옆 검색창에 `cmd` 라고 칩니다
2. **명령 프롬프트** 를 눌러 엽니다
3. 까만 창이 하나 뜹니다. 거기에 아래를 치고 엔터를 누르세요

![검색창에 cmd 를 쳤을 때 맨 위에 나오는 명령 프롬프트](/samples/guides/lab-11-3.jpg)

```
git --version
```

이런 줄이 나오면 성공입니다.

```
git version 2.55.0.windows.1
```

![명령 프롬프트에서 git --version 을 쳤더니 git version 줄이 나온 화면](/samples/guides/lab-11-4.png)

숫자는 달라도 됩니다. `git version` 으로 시작하는 줄이 나오면 된 겁니다.
**확인은 까만 창에서만** 하세요. 코워크에 물어보면 엉뚱한 답이 나옵니다 — 이유는 아래 도전에서 설명합니다.

**이런 게 나오면 아직입니다**

```
'git'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램,
또는 배치 파일이 아닙니다.
```

| 이럴 땐 | 이렇게 |
|---|---|
| 설치가 덜 끝났다 | 설치 창이 아직 떠 있는지 확인하고, 끝까지 넘기세요 |
| 창을 미리 열어뒀다 | 까만 창을 닫고 다시 열어 보세요. 열려 있던 창은 못 알아봅니다 |
| 그래도 안 된다 | 컴퓨터를 **다시 시작**한 뒤 한 번 더 쳐보세요 |

## 이렇게 되면 성공이에요

- 내려받기 폴더에 설치 파일이 1개 생겼다
- 설치가 끝까지 넘어가 마지막 화면이 나왔다
- 까만 창에서 `git version …` 줄이 나왔다
- 그 화면을 캡처해 두었다

## 수업 마치고 — 한 번 껐다 켜기

수업이 끝나면 컴퓨터를 **다시 시작**해 주세요. 전원을 껐다 켜는 것보다 「다시 시작」이 확실합니다.

켜지면 Claude 앱을 열고, 왼쪽 위에서 `</> Code` 칸을 한 번 눌러봅니다.

- 그냥 열린다 → 준비 끝입니다
- 뭔가 더 필요하다는 안내가 뜬다 → 안 열려도 괜찮습니다. 미리 알려주시면 빨리 풀립니다

## 직접 해보기 (도전)

코워크에도 물어보고, 답이 왜 다른지 알아봅니다.

반드시 오늘 만든 `sales_report` 프로젝트를 열고 물어보세요. 새 대화에서 물으면 답을 못 합니다.

```
내 컴퓨터에 git 이 설치되어 있는지 확인하고
설치되어 있으면 버전을 알려줘.
없으면 없다고만 말해줘. 지어내지 마.
```

![코워크가 git 2.34.1 이라고 답하면서, 이건 작업용 리눅스 환경의 git이라 윈도우 쪽은 따로 확인해야 한다고 짚어준 화면](/samples/guides/lab-11-6.png)

**새 대화에서 물으면** "연결된 폴더가 없어서 셸을 실행할 수 없습니다. 명령 실행 권한이 폴더 단위로 열립니다." 라고 나옵니다.
고장이 아닙니다. 실습 6에서 말한 「허락한 방만 열리는 열쇠」가 여기서도 그대로입니다.
폴더를 안 붙여두면 파일만 못 보는 게 아니라 아무것도 실행하지 못합니다.

**왜 답이 다를까요.** 둘 다 맞는 답입니다. 다른 곳을 본 것뿐입니다.

- **까만 창** — 내 윈도우에 깐 것. 우리가 방금 설치한 그것
- **코워크** — 앱이 자기 안에 띄워둔 작업 공간. 거기에도 git이 이미 들어 있습니다

앱은 자기만의 작업 공간을 하나 더 갖고 있습니다. 앞에서 엑셀 파일 만들 때
"필요한 도구를 설치해도 되냐" 고 물었던 것, 거기에 설치한 겁니다.
그러니까 컴퓨터에 git이 두 군데 있는 셈입니다.

우리가 필요한 건 윈도우 쪽입니다. 다음 회차에 열 `</> Code` 칸이 보는 게 그쪽이거든요.
그래서 확인은 까만 창에서 해야 정확합니다. 숫자가 다르다고 설치가 잘못된 게 아닙니다.

코워크가 "이건 리눅스 쪽 git이고, 윈도우 쪽은 따로 확인하셔야 합니다" 라고 짚어주면
그게 지어내지 않는 태도입니다. 앞 실습에서 배운 환각의 반대편이에요.
