# ClassFlow 기능 명세서

최종 정리: 2026-09-23

이 문서는 사용자와의 대화에서 나온 제품 요구사항과 최신 결정을 기록한다. 기능 범위와 우선순위는 이 문서를 기준으로 한다. 기존 `task.md`의 체크박스와 README는 과거 구현 기록을 포함하므로, 현재 배포 상태의 증거로 사용하지 않는다.

**요구사항에 기록되었다는 사실은 구현·배포 완료를 의미하지 않는다.** 아래 완료 기준은 향후 구현과 검증에 사용할 기준이다. 구현 여부는 해당 코드와 배포본에서 별도로 확인한다.

## 1. 개발 목적

강사가 노션으로 실습을 안내하고, Mentimeter로 퀴즈를 진행하고, 오픈채팅으로 결과물을 받으며 여러 채널을 오가는 비효율을 줄인다. 기존 교안을 중심으로 설명·학생 참여·실습·결과물 공유를 연결한다. 수업 후에도 학생이 이전 자료를 찾아 복습할 수 있게 한다.

## 2. 최신 결정과 개발 순서

### 사용자 확정 사항

- **가장 먼저 PPT 업로드와 PPT → PDF 변환·저장·다운로드를 구현한다.** 채팅·마이페이지보다 우선한다.
- 업로드 진입점을 **일반 수업용 업로드 / AI 퀴즈·실습 추출용 업로드**로 나눈다.
- 향후 **AI 기능만 유료화할 수 있게** 일반 변환·저장과 AI 실행을 분리한다. 지금 결제 도입을 확정한 것은 아니다.
- 장기 운영을 위해 AWS Lightsail을 사용하는 방향으로 진행한다. 서버 생성 완료를 의미하지 않는다.
- 학생이 지난 자료를 계속 볼 수 있는 내 강의실을 제공한다. 현재 노션 자료를 오래 공개하는 운영 방식을 이어가는 것이 목표다.
- 진행 중인 수업에는 오른쪽 위 **LIVE**, 그 외 복습 가능한 수업에는 **복습** 태그를 표시한다.
- **최신 작업 지시:** 불러온 교안 중간에 이미지·실시간 워드클라우드 페이지를 추가한다. 강사 화면에만 현재 페이지 앞/뒤 `+` 버튼을 제공한다. 우선 로컬에서 수정·검증하며 서버 배포·Git push는 하지 않는다.
- 진행 상태는 [개발 체크리스트](development-checklist.md)에서 요구사항과 분리해 관리한다.

### 실행 순서

| 순서 | 범위 | 성격 |
| --- | --- | --- |
| 1 | Lightsail 준비, PPT 업로드·PDF 변환·공유 저장·다운로드 | 사용자 최우선 |
| 2 | 두 업로드 경로 분리, PPT 기반 AI 퀴즈·실습 추출 및 검토 | 사용자 추가 요구, 1번과 함께 설계 |
| 공통 | 다른 기기 공유, 변환 실패 복구, 동시 참여·폴링 비용 검증 | 각 단계 출시 조건 |
| 3 | 수업별 채팅 | 후속 제안 순서 |
| 4 | 로그인·학생/강사 내 강의실, LIVE/복습 모드 | 후속 제안 순서 |
| 5 | 추가자료 첨부·장기 보관, 마이페이지 확장 | 후속 제안 순서 |

3번 이후의 순서는 아직 사용자 최종 확정이 아니다. 실제 수업에서 복습 제공이 먼저 필요하면 내 강의실을 채팅보다 앞당긴다.

## 3. 자료 업로드와 변환

### UP-01. 일반 수업용 업로드

- 버튼 문구 제안: **자료 올려 수업 시작**. 화면에서 PPTX/PDF 지원 범위를 명확히 안내한다.
- PPTX 업로드 → 서버에서 PDF 변환 → 공유 파일 저장소 저장 → 수업에 연결한다.
- 기존 PDF 업로드는 변환 없이 공유 저장소에 저장한다.
- 일반 경로에서는 Claude API를 호출하지 않는다. 발표자 노트의 일반 추출은 AI 호출과 분리한다.
- 학생은 강사가 업로드한 브라우저가 아닌 휴대폰·다른 기기에서도 동일한 자료를 볼 수 있어야 한다.
- 강사는 변환된 PDF를 내려받을 수 있어야 한다.
- 업로드·변환·저장 중 현재 작업을 표시하고, 실패 시 원인과 재시도 방법을 안내한다.
- 공유 저장 실패를 수업 준비 성공으로 표시하지 않는다. 로컬에만 남는 경우 학생에게 보이지 않는다는 점을 명확히 알린다.
- 원본 PPTX를 보관할지, 보관 기간과 삭제 정책은 별도 결정한다. PDF의 공유 저장은 필수다.
- 구형 `.ppt` 지원은 미확정이다. 초기 구현은 PPTX를 기준으로 하며 지원하지 않는 확장자는 명확히 안내한다.

완료 기준: 실제 한글 PPTX를 올려 변환·다운로드하고, 강사와 별도 학생 기기에서 페이지 수·슬라이드 표시·동기화를 확인한다. 한글 폰트, 이미지, 표 등의 변환 품질도 확인한다.

### UP-02. AI 수업용 업로드

- 버튼 문구 제안: **AI로 퀴즈·실습 만들기**.
- PPTX의 제목·발표자 노트(강의 대본)를 읽어 강의 맥락에 맞는 퀴즈와 실습 초안을 추출·생성한다.
- 기존 제목 기반 퀴즈·실습 위치 감지와 연결하고, 제목으로 위치를 감지한 것과 AI가 내용을 생성한 것을 구분한다.
- 생성된 질문·선택지·정답, 실습 안내와 연결 슬라이드를 강사가 확인·수정한 후 적용한다.
- 일반 업로드 이후에도 AI 기능을 추가 실행할 수 있도록 설계한다.
- 발표자 노트가 없거나 내용이 부족하면 AI 실행 전에 안내한다. 근거 없는 내용을 임의로 완성하지 않는다.
- 별도 **대본 PPTX 추가** 버튼은 제거 요청을 유지한다. PPT 자체 업로드에서 노트를 함께 처리한다.
- PDF만 업로드했을 때 AI 생성은 막는다. 클릭하면 **“해당 기능은 발표자 노트가 포함된 PPT에서만 사용 가능합니다.”**라고 안내한다.
- PPT 업로드가 정식 지원되면 과거 PDF 전용 문구와 온보딩도 실제 지원 범위에 맞춰 변경한다.

### UP-03. 파일 제한

- PDF 페이지 수·파일 용량 제한을 화면에서 구분해 안내한다.
- 사용자는 업로드 한도 확대 방법을 질문했으며, 새 제한값은 확정하지 않았다. 임의로 100MB 등으로 변경하지 않는다.
- PPTX 용량, 변환 시간, PDF 결과 용량, 동시 변환 수는 실제 교안 테스트 후 정한다.

## 4. AI 생성과 향후 유료화

### AI-01. 퀴즈 작성 규칙

- 사용자의 `lecture-harness` 퀴즈 작성 규칙을 AI 생성에도 적용한다.
- 적용 규칙과 검사 범위는 [AI 퀴즈 작성 규칙](ai-quiz-rules.md)을 따른다.
- 질문·선택지·정답을 생성하고, 정답의 명확성·오답의 타당성·선택지 표현·정답 분산을 검토한다.
- 생성 결과는 강사가 검토할 수 있어야 한다. 자동 검사가 의미적 정확성까지 보장한다고 표시하지 않는다.

### AI-02. 가벼운 학생 참여 질문

- 지식 확인 퀴즈 외에 경험 묻기, 사용 수준 묻기, 상황 OX를 제공한다.
- 예: “이런 경험 있으신 분?”, “어디까지 써보셨나요?”, “이 상황에서는 맞을까요, 틀릴까요?”
- 경험·사용 수준 질문에는 정답을 두지 않는다. 미경험자도 답할 수 있도록 선택지를 만든다.
- 상황 OX는 근거가 있는 정답형 문항으로 구분한다.

### AI-03. 과금 가능한 기능 분리

- 일반 업로드·PDF 변환·저장과 AI 분석 API의 실행 경로를 분리한다.
- 유료화 시 AI 실행 전에 서버에서 이용 권한과 사용 가능량을 확인할 수 있게 설계한다. 버튼 숨김만으로 제한하지 않는다.
- AI 실행별 사용자·수업·실행 상태·사용량을 기록할 수 있게 한다.
- 재시도·중복 클릭으로 중복 실행 또는 중복 차감이 생기지 않게 한다.
- 가격, 무료 체험 횟수, 구독/크레딧 방식, 결제사, 실패 시 차감 정책은 **미정**이다.
- 일반 기능의 영구 무료 제공까지 확정한 것은 아니다. 확정된 방향은 **AI 기능을 별도로 유료화할 수 있는 구조**다.

## 5. 실시간 수업과 발표

### EDIT-01. 교안 사이에 페이지 추가 (현재 로컬 구현 대상)

- PPT에서 변환한 PDF 또는 직접 올린 PDF/샘플의 원하는 페이지 앞뒤에 새 페이지를 끼워 넣는다.
- `＋ 이 페이지 앞에 추가`, `＋ 이 페이지 뒤에 추가` 버튼은 **강사 화면에만** 표시한다. 위/아래가 아니라 **슬라이드 왼쪽/오른쪽 중앙의 원형 + 버튼**으로 배치한다. 선택창은 아래에 열린다. API도 강사 권한을 확인한다.
- 페이지 종류: **이미지 / 실시간 워드클라우드**.
- 이미지: 파일 선택 또는 Ctrl+V로 첨부하고 한 페이지로 표시한다.
- 워드클라우드: 강사가 질문을 입력하면 학생이 단어·짧은 표현으로 참여한다. 같은 표현은 집계하고 많이 나온 단어를 크게 표시한다.
- 초기 정책: 한 학생당 한 표현, 다시 제출하면 변경, 20자 이내. 조사 제거·의미가 비슷한 단어 합치기는 미구현이다.
- 학생은 강사가 선택한 추가 페이지를 함께 보며 워드클라우드에 참여한다. 강사 화면에는 결과를 표시한다.
- 원본 PDF를 수정하지 않고 수업 내 페이지 구성을 별도 저장한다.
- **수업 PDF 다운로드**에는 추가한 페이지까지 현재 순서대로 포함한다. 원본 PDF 페이지는 보존하고 이미지 페이지와 워드클라우드 결과를 합친 새 PDF를 만든다.
- 워드클라우드는 다운로드 시점의 질문·집계 결과를 정적인 페이지로 담는다. PDF 안에서 실시간 입력은 제공하지 않는다.
- 이번 PDF 내보내기는 원본 슬라이드와 추가 페이지가 대상이며, 별도 퀴즈 UI·실습 가이드·판서를 함께 내보내는 것은 후속 범위다.
- 삽입으로 기존 PDF 페이지·퀴즈 응답·실습 가이드·게시판 제출물·판서의 연결이 어긋나지 않아야 한다.
- 새로고침과 전체화면 발표에서도 추가 페이지와 응답이 유지되어야 한다.
- 이번 검증은 로컬 전용 저장소를 사용한다. 운영 Redis/Blob에 테스트 데이터를 쓰거나 배포하지 않는다.
- 추가 페이지 삭제·순서 변경은 별도 후속 범위다.

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| LIVE-01 | 강사/학생 토글, 역할 표시를 더 크게 | 현재 역할을 쉽게 구분하고 같은 수업에서 전환 가능 |
| LIVE-02 | 강사 슬라이드와 학생 화면 동기화 | 다른 기기에서도 따라가며 재접속 시 현재 상태 복구 |
| LIVE-03 | 학생 퀴즈 응답·실시간 집계·정답 공개 | 단일/복수 선택·답 변경·공개 상태가 일관됨 |
| LIVE-04 | 강사가 퀴즈를 클릭하면 학생 전용 안내 | 문항 아래 학생 화면에서만 답할 수 있다는 안내, 응답 저장 없음 |
| LIVE-05 | 학생 링크 복사 피드백 | 성공 시 **복사됐어요!** 표시. 실패를 성공으로 표시하지 않음 |
| LIVE-06 | 학생 초대 설명을 일상적인 문구로 변경 | 공개 사이트에서 localhost·같은 서버 등 개발 용어 대신 링크로 참여 안내 |
| LIVE-07 | 여러 이모지가 슬라이드 위로 떠오르는 반응 | 학생이 연속 클릭 가능, 강사·학생 화면에 실시간 표시 |
| LIVE-08 | 전체화면 발표·판서 | 도구·색·굵기·되돌리기·지우기 제공, 좁은 화면에서도 지우기 버튼이 잘리지 않음 |
| LIVE-09 | 판서 Ctrl+Z 취소 | 판서 활성 시 마지막 작업 취소. 입력창 편집과 충돌하지 않음. Cmd+Z도 지원 방향 |
| LIVE-10 | PPT 같은 발표자 보기 | 빔에는 슬라이드만 표시하고 강사에게만 대본 표시. 확장 화면/별도 발표 창 등 출력 분리 필요 |

발표자 대본은 학생용 API에도 노출하지 않는다. 같은 화면에 대본 패널만 추가하는 것으로 “강사에게만 보임” 요구를 충족한 것으로 처리하지 않는다.

## 13. 로컬 구현 현황 (2026-09-23)

일반 PPTX·PDF 업로드를 로컬 강사 화면에 연결했다. LibreOffice로 PPTX를 PDF로 변환하고 PDF·발표자 노트를 로컬 파일 저장소에 보관한다. PDF는 학생 화면에 제공하고 노트 조회는 강사만 허용한다. 일반 업로드는 AI를 자동 호출하지 않는다. 현재 테스트 한도는 PPTX 200MB, 결과 PDF 60MB다. Lightsail 연결, 별도 AI 업로드에서 퀴즈·실습 초안을 일괄 생성하고 검토하는 흐름, 과금은 미구현이다. 자세한 검증 결과는 개발 체크리스트에 기록한다.

### 역할별 다운로드 요구 (2026-09-23 추가)

- 강사 화면: 업로드한 원본 PPTX와 수업 PDF를 다운로드한다.
- 학생 화면: 수업 PDF를 다운로드한다. 원본 PPTX와 발표자 노트는 제공하지 않는다.
- 원본 PPTX는 그대로 보관한다. 수업 중 삽입한 페이지까지 포함하는 출력은 PDF로 제공한다.
- PDF만 올린 수업은 PDF 다운로드만 제공한다.

## 실시간 참여 질문 표시 방식

슬라이드 앞/뒤의 추가 버튼에서 `실시간 참여 질문`을 고르고 표시 방식을 선택한다. 워드클라우드는 기존 짧은 단어 입력, 서술형 카드는 500자 이내 긴 답변, 막대·파이·도넛은 2~10개의 선택지에 응답한다. 선택형은 단일/복수 선택을 설정할 수 있다. 복수 선택 차트의 비율은 전체 선택 수 기준이다. 동일 참가자의 재제출은 이전 답변을 바꾸며 현재 페이지에서만 제출할 수 있다.

PDF 다운로드는 다운로드 시점의 응답 결과를 포함한다. 카드 답변이 한 장에 들어가지 않으면 이어지는 페이지에 모두 출력하고 실제 출력 페이지 수를 안내한다. 로컬 전용 격리 수업에서 검증했으며 배포 반영은 별도다.

## 14. PPT 서버 변환 연결 (2026-09-23)

기존 Vercel 주소에서 PPTX 업로드를 지원한다. 브라우저에서 원본을 AES-GCM으로 암호화해 Blob으로 직접 올리고, 서울 Lightsail의 outbound agent가 작업을 가져와 LibreOffice로 PDF를 생성한다. 추가 도메인·공개 변환 포트는 사용하지 않는다. 변환 완료 후에만 수업 자료를 교체하며, 실패하면 기존 수업을 유지한다. 새로고침 후 ‘변환 결과 확인’으로 이어볼 수 있다.

강사는 원본 PPTX를 복호화해 다운로드하고 발표자 노트를 AI 질문 생성에 사용할 수 있다. 학생은 공유 PDF만 제공받는다. 일반 PPT 업로드는 AI를 자동 호출하지 않는다. AI 일괄 퀴즈·실습 추출을 별도 유료 업로드로 분리하는 기능은 아직 미완료다.

시험 운영 제한: PPTX 200MiB, PDF 60MiB, 동시 변환 1건, 대기열 5건, UTC 하루 20회, PPT 원본+최대 PDF 크기를 합한 보관 예약 512MiB. 실패한 작업도 보수적으로 예약량에 포함하며 자동 삭제하지 않는다. 운영 규모를 키우기 전 자료 삭제·보관 정책과 제한 조정이 필요하다. AWS/Vercel 전체 비용을 차단하는 기능은 아니다.

실제 운영 API 및 강사 업로드 UI에서 36MB/41쪽 샘플 변환과 학생 PDF 표시를 확인했다. 추가 페이지·설문 삽입 UI는 기존 요청대로 로컬에만 노출한다.

## PPT 기존 퀴즈 자동 불러오기와 새 퀴즈 생성 구분
- PPT 업로드 완료 시 제목으로 감지한 퀴즈 페이지의 기존 문제·선택지는 렌더된 페이지 이미지에서 읽고, 정답은 발표자 노트에서 확인한다. 대괄호 유무와 무관하게 퀴즈로 감지한다.
- 기존 문제를 옮길 때 선택지 순서를 바꾸거나 새로운 문항을 만들지 않는다. OCR/정답 확인에는 Claude API를 사용한다.
- PDF 업로드에는 자동 추출을 실행하지 않는다. 새 문항 생성은 별도의 ‘AI로 퀴즈 만들기’를 사용한다.
- 추출은 페이지별로 진행하고 즉시 저장한다. 노트 없음/추출 거절/시간 초과는 해당 페이지 사유를 보여주고 다음 페이지를 진행한다.
- ‘PPT 퀴즈 다시 불러오기’는 문항이 없는 페이지만 대상으로 한다. 서버에서 같은 페이지 중복 저장 및 자료가 교체된 뒤 저장을 차단한다.
- 원문을 읽지 못하면 추측한 정답을 저장하지 않는다. 수동 입력 경로를 유지한다.


## 실시간 수업 채팅 — 2026-09-26

- 슬라이드 옆 접이식 채팅 패널. 슬라이드를 바꿔도 대화는 수업 단위로 이어진다.
- 학생은 첫 채팅 입장 시 이름/닉네임을 입력하며 같은 브라우저에서는 기억한다. 이름 변경 가능.
- 강사가 단계 번호를 보내면 학생은 해당 메시지에 완료 이모지로 반응하고, 막힌 학생은 질문을 남긴다.
- 강사만 진행 확인 메시지 한 개를 고정할 수 있으며 반응한 사람과 미반응 참여자를 확인한다.
- Zoom/Slack 방식으로 메시지 위에 마우스를 올릴 때 이모지 선택기와 핀 아이콘을 표시한다. 이미 달린 이모지와 개수는 항상 표시한다. 키보드 초점/터치 버튼도 지원한다.
- 메시지·반응·고정 상태는 수업 상태와 분리한 PostgreSQL에 저장한다. 샘플 교체로 채팅을 초기화하지 않는다.
- 2026-09-26 기존 Lightsail의 PostgreSQL/Socket.IO/Caddy와 무료 sslip.io HTTPS/WSS 주소로 Production 활성화. 제출한 Vercel 웹 주소는 유지한다. 배포 브라우저 기능 검증 완료; 외부 자동 백업·실제 복원·모바일 실기기·운영 동시 부하는 별도 남은 항목이다.
- 세부 운영 절차와 한계는 `chat-server/README.md`, 진행 상태는 `development-checklist.md` 참조.
